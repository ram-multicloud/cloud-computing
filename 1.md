## Topic: Virtual Machines in AWS (EC2 Fundamentals)

## What is an EC2 Instance?

An **EC2 (Elastic Compute Cloud) instance** is AWS's virtual machine — a resizable compute unit you rent by the hour/second, running in AWS's data centers instead of on your own hardware.

Think of EC2 like renting a fully furnished apartment instead of building a house: AWS owns the physical server, and you get an isolated, ready-to-use "unit" of compute.

## Core Building Blocks

| Concept | AWS Term | What It Means | Analogy |
|---|---|---|---|
| Virtual machine | **EC2 Instance** | The compute unit itself — the "server" | The apartment |
| Storage | **EBS (Elastic Block Store)** | Persistent disk attached to the instance | The apartment's storage room |
| Sizing | **Instance Type** | Defines CPU + memory (e.g., t2.micro, m5.large) | Studio vs. 3-bedroom apartment |
| Networking | **Public IP (Static/Elastic IP)** | The address used to reach the instance from the internet | The apartment's street address |
| Access control | **Security Group** | A virtual firewall controlling traffic | The building's security desk |
| Login credential | **Key Pair** | SSH public/private key used for secure login | The apartment's front door key |
| Software | **Operating System (AMI)** | Linux, Windows, or Mac base image | Furnishing style of the apartment |

## Security Groups — The Firewall Layer

A security group controls **what traffic is allowed in and out** of an instance. It works with two types of rules:

| Rule Type | Direction | Example |
|---|---|---|
| **Inbound rule** | Traffic coming *into* the instance | Allow SSH (port 22) from your IP |
| **Outbound rule** | Traffic leaving the instance | Allow all outbound (default) so the instance can reach the internet |

**Key idea:** By default, all inbound traffic is denied and all outbound traffic is allowed — you must explicitly open ports (like 22 for SSH, 80 for HTTP) that you need.

## Key Pairs — How You Log In Securely

Instead of a password, AWS uses **public/private key cryptography**:

- **Public key** → stored by AWS, placed on the instance automatically
- **Private key (.pem file)** → downloaded once by you, kept secret, used to prove your identity

You can either:
- **Create** a new key pair (AWS generates both keys, you download the private one), or
- **Import** an existing public key you already have

> ⚠️ If you lose the `.pem` file, AWS cannot regenerate it — you'd need to detach the volume and use a workaround, or launch a new instance.

## Connecting to Your EC2 Instance

There are two ways to SSH into an instance:

```bash
# Option 1: Password-based login (if enabled)
ssh username@ipaddress
# → prompts for a password

# Option 2: Key-based login (standard/secure method)
ssh -i <path-to-pemfile> user@ipaddress
```

**Best practice:** Always prefer key-based login (Option 2). Password-based SSH is less secure and often disabled by default on cloud images.

## Worked Example — Installing Apache on Ubuntu

Once connected to an Ubuntu EC2 instance, install a web server:

```bash
sudo apt-get update                  # refresh package index
sudo apt-get install apache2 -y      # install Apache web server
sudo systemctl status apache2        # verify it's running
```

Then verify it's serving traffic by visiting:

```
http://<ipaddress>
```
