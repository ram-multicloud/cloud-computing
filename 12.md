# Azure Function — Start/Stop VMs by Tag (Complete Guide)

End-to-end guide: create the Function App, understand trigger types, required permissions, folder structure, sample code, zipping, and deployment.

---

## 1. Trigger Types (which one to use and why)

| Trigger Type | When to use | Example |
|---|---|---|
| **HTTP Trigger** | Manual/on-demand start-stop via API call, Postman, curl, or another app | `GET/POST /api/vm-control?action=start` |
| **Timer Trigger** | Scheduled auto start/stop (e.g. stop all dev VMs at 7 PM daily) | CRON `0 0 19 * * *` |
| **Queue Trigger** | Decoupled/async — another system drops a message ("stop VM X") into a Storage Queue | Useful for event-driven automation |
| **Event Grid Trigger** | React to Azure events (e.g. VM created → auto-tag it) | Native Azure event integration |

This guide uses **HTTP Trigger** (manual control) — the same VM logic can be reused under a Timer Trigger by removing the `req` parameter handling.

---

## 2. Permissions Required

### A. Azure RBAC role (for the Function to control VMs)
The Function App's **Managed Identity** needs a role that can start/deallocate/read VMs:

| Role | Scope | Purpose |
|---|---|---|
| **Virtual Machine Contributor** | Subscription or Resource Group | Start, stop, deallocate, restart VMs |
| **Reader** (optional, narrower alternative) | Subscription | If you only need to *list* VMs/tags, not act — not sufficient alone for start/stop |

> Use **Resource Group** scope instead of Subscription scope if you want to restrict which VMs the function can touch.

### B. Identity type
- **System-Assigned Managed Identity** (recommended) — tied to the Function App's lifecycle, no secrets to manage.
- Avoid using a Service Principal with client secret unless Managed Identity isn't an option — secrets require rotation and secure storage (e.g. Key Vault).

### C. Function-level auth (who can call the function itself)
Set in `function.json` → `authLevel`:

| authLevel | Who can call it |
|---|---|
| `anonymous` | Anyone with the URL — no key required |
| `function` | Requires a function key in the URL/header (recommended default) |
| `admin` | Requires the master key (highest privilege, avoid for routine use) |

### D. Deployment permissions (your own account, not the Function's identity)
To create resources and deploy, your `az login` account needs:
- **Contributor** (or **Owner**) on the target Resource Group/Subscription
- Permission to create **Role Assignments** if you're the one granting the Managed Identity its role (`User Access Administrator` or `Owner`)

## 3. Tag Your VMs

The function only acts on VMs carrying a specific tag key/value — set this first:

```bash
az vm update \
  --resource-group <resource-group-name> \
  --name <vm-name> \
  --set tags.AutoManage=true
```

You can use any key/value pair; this guide uses `AutoManage=true`.

### VMControl/__init__.py

```python
import logging
import os
import azure.functions as func

from azure.identity import DefaultAzureCredential
from azure.mgmt.compute import ComputeManagementClient
from azure.mgmt.resource import ResourceManagementClient

SUBSCRIPTION_ID = os.environ["AZURE_SUBSCRIPTION_ID"]

# Tag key/value used to filter which VMs this function is allowed to control
TAG_KEY = os.environ.get("TARGET_TAG_KEY", "AutoManage")
TAG_VALUE = os.environ.get("TARGET_TAG_VALUE", "true")


def main(req: func.HttpRequest) -> func.HttpResponse:

    logging.info("HTTP trigger: VM start/stop by tag")

    # Accept action from query string OR JSON body
    action = req.params.get("action")

    if not action:
        try:
            req_body = req.get_json()
        except ValueError:
            req_body = {}
        action = req_body.get("action")

    if not action or action not in ("start", "stop"):
        return func.HttpResponse(
            "Please pass action=start or action=stop (query param or JSON body)",
            status_code=400
        )

    credential = DefaultAzureCredential()

    compute_client = ComputeManagementClient(credential, SUBSCRIPTION_ID)
    resource_client = ResourceManagementClient(credential, SUBSCRIPTION_ID)

    results = []

    for rg in resource_client.resource_groups.list():

        for vm in compute_client.virtual_machines.list(rg.name):

            tags = vm.tags or {}

            # Filter: only act on VMs matching the configured tag key/value
            if tags.get(TAG_KEY, "").lower() != TAG_VALUE.lower():
                continue

            vm_name = vm.name

            try:
                if action == "start":
                    compute_client.virtual_machines.begin_start(rg.name, vm_name)
                    results.append(f"Started VM: {vm_name} (RG: {rg.name})")

                elif action == "stop":
                    compute_client.virtual_machines.begin_deallocate(rg.name, vm_name)
                    results.append(f"Stopped VM: {vm_name} (RG: {rg.name})")

            except Exception as ex:
                logging.error(f"Failed to {action} {vm_name}: {ex}")
                results.append(f"{vm_name}: FAILED - {ex}")

    if not results:
        return func.HttpResponse(
            f"No VMs found with tag {TAG_KEY}={TAG_VALUE}",
            status_code=200
        )

    return func.HttpResponse("\n".join(results), status_code=200)
```

## 6. Create the Azure Function App (CLI)

```bash
# Variables
RESOURCE_GROUP="rg-vm-control"
LOCATION="eastus"
STORAGE_ACCOUNT="stvmcontrol$RANDOM"
FUNCTION_APP="func-vm-control-$RANDOM"

az login

# Resource group
az group create \
  --name $RESOURCE_GROUP \
  --location $LOCATION

# Storage account (required by every Function App)
az storage account create \
  --name $STORAGE_ACCOUNT \
  --location $LOCATION \
  --resource-group $RESOURCE_GROUP \
  --sku Standard_LRS

# Function App — Linux, Python, Consumption (serverless) plan
az functionapp create \
  --resource-group $RESOURCE_GROUP \
  --consumption-plan-location $LOCATION \
  --runtime python \
  --runtime-version 3.9 \
  --functions-version 4 \
  --os-type Linux \
  --name $FUNCTION_APP \
  --storage-account $STORAGE_ACCOUNT
```

## 7. Enable Managed Identity & Assign Permissions

```bash
SUBSCRIPTION_ID=$(az account show --query id -o tsv)

# Enable system-assigned managed identity
az functionapp identity assign \
  --name $FUNCTION_APP \
  --resource-group $RESOURCE_GROUP

# Grab the identity's principal ID
PRINCIPAL_ID=$(az functionapp identity show \
  --name $FUNCTION_APP \
  --resource-group $RESOURCE_GROUP \
  --query principalId -o tsv)

# Grant Virtual Machine Contributor (subscription scope shown; narrow to a RG if preferred)
az role assignment create \
  --assignee $PRINCIPAL_ID \
  --role "Virtual Machine Contributor" \
  --scope /subscriptions/$SUBSCRIPTION_ID
```

## 8. Configure App Settings

```bash
az functionapp config appsettings set \
  --name $FUNCTION_APP \
  --resource-group $RESOURCE_GROUP \
  --settings \
    AZURE_SUBSCRIPTION_ID=$SUBSCRIPTION_ID \
    TARGET_TAG_KEY=AutoManage \
    TARGET_TAG_VALUE=true \
    SCM_DO_BUILD_DURING_DEPLOYMENT=true
```

> `SCM_DO_BUILD_DURING_DEPLOYMENT=true` ensures Python dependencies in `requirements.txt` are actually installed on deploy — without it, zip deploys can succeed but the function fails at runtime with import errors.

## 10. Zip the Project for Deployment

Run **from inside** `vm-control-function` so files sit at the zip root (not inside a wrapping folder):

**macOS / Linux:**
```bash
cd vm-control-function
zip -r ../vm-control-function.zip . -x ".venv/*" -x "__pycache__/*" -x "*.pyc"
```

**Windows (PowerShell):**
```powershell
cd vm-control-function
Compress-Archive -Path .\* -DestinationPath ..\vm-control-function.zip -Force
```

Correct structure inside the zip:
```
vm-control-function.zip
├── VMControl/
│   ├── __init__.py
│   └── function.json
├── requirements.txt
└── host.json
```

> ⚠️ If the zip contains one top-level folder (e.g. `vm-control-function/VMControl/...`) instead of the files directly, deployment will fail or the function won't be discovered.

## 11. Deploy the Zip

**Option A — Functions Core Tools (handles remote build automatically):**
```bash
cd vm-control-function
func azure functionapp publish $FUNCTION_APP
```

**Option B — Azure CLI zip deploy:**
```bash
az functionapp deployment source config-zip \
  --resource-group $RESOURCE_GROUP \
  --name $FUNCTION_APP \
  --src vm-control-function.zip
```

## 12. Get the Function URL & Key, Then Trigger It

```bash
FUNC_KEY=$(az functionapp function keys list \
  --resource-group $RESOURCE_GROUP \
  --name $FUNCTION_APP \
  --function-name VMControl \
  --query default -o tsv)

echo "https://$FUNCTION_APP.azurewebsites.net/api/vm-control?code=$FUNC_KEY&action=start"
```

**Trigger via query string:**
```bash
curl "https://$FUNCTION_APP.azurewebsites.net/api/vm-control?code=$FUNC_KEY&action=start"
curl "https://$FUNCTION_APP.azurewebsites.net/api/vm-control?code=$FUNC_KEY&action=stop"
```

**Trigger via JSON request body:**
```bash
curl -X POST "https://$FUNCTION_APP.azurewebsites.net/api/vm-control?code=$FUNC_KEY" \
  -H "Content-Type: application/json" \
  -d '{"action": "start"}'
```

## 13. Troubleshooting Checklist

| Symptom | Likely Cause | Fix |
|---|---|---|
| Fails in ~10ms, no logic reached | `AZURE_SUBSCRIPTION_ID` app setting missing | Set it via Step 8 |
| `ModuleNotFoundError` at runtime | Dependencies not installed during deploy | Set `SCM_DO_BUILD_DURING_DEPLOYMENT=true` and redeploy |
| `AuthorizationFailed` calling Compute API | Managed Identity missing role assignment | Re-run Step 7 |
| 401/403 calling the function URL | Wrong/missing function key, or wrong route path | Use `/api/vm-control`, confirm key with `function keys list` |
| "No VMs found with tag..." | No VM has the matching tag key/value | Tag a VM as shown in Step 3 |

**Live log tail while testing:**
```bash
az functionapp log tail --name $FUNCTION_APP --resource-group $RESOURCE_GROUP
```
