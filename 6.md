# Creating a VM Image in Azure & Azure Compute Gallery

## What is a VM Image (Azure)

A **VM Image** is a template captured from an existing (generalized) virtual machine — OS disk, data disks, and configuration — that can be used to create new VMs quickly, with the same OS, installed software, and settings already baked in.

- **Generalized image**: source VM has been de-provisioned (via `sysprep` for Windows or `waagent deprovision` for Linux) so machine-specific info (hostname, SIDs, etc.) is removed. Can be used to create multiple new VMs.
- **Specialized image (snapshot-based)**: retains machine-specific info. Used to create a copy of a specific VM (e.g., for backup/recovery), not for mass deployment.

## Steps to Create a VM Image — Azure Portal UI

1. **Prepare the source VM**
   - Stop the VM.
   - If creating a *generalized* image, connect to the VM and run:
     - Windows: `sysprep /oobe /generalize /shutdown`
     - Linux: `sudo waagent -deprovision+user -force` then deallocate (or via Azure CLI: `az vm deallocate` + `az vm generalize`)

2. **Deallocate the VM**
   - In the Azure Portal, go to the VM → click **Stop** (ensures the VM shows as "Stopped (deallocated)").

3. **Capture the image**
   - On the VM's **Overview** page, click **Capture** (top menu).
   - Choose:
     - **Create image** (standalone managed image), or
     - **Share image to a gallery** (recommended — see Gallery section below).
   - If using a gallery, select or create the **Gallery**, **Image Definition**, and **Image Version**.

4. **Name and configure**
   - Provide a name, resource group, and confirm data disk settings.

5. **Review + Create**
   - Click **Review + create** → **Create**. Azure captures the disk(s) and produces the image resource.

6. **Use the image**
   - Go to **Create a VM** → under **Image**, select **See all images** → choose your captured image from **My Images** or the gallery.

## Azure Compute Gallery (formerly Shared Image Gallery)

### Definition

**Azure Compute Gallery** is a repository service for managing and sharing VM images at scale. It organizes images hierarchically and supports **versioning**, **regional replication**, and **access control** — so images can be shared across subscriptions, tenants, or the wider organization, unlike a standalone managed image, which is single-region and harder to share.

### Hierarchy

```
Azure Compute Gallery
 └── Image Definition (e.g., "webserver-ubuntu-2204")
      └── Image Version (e.g., 1.0.0, 1.0.1, 2.0.0)
           └── Replicated to one or more regions
```

- **Gallery**: the top-level container — a named resource that groups related image definitions.
- **Image Definition**: describes a *type* of image — OS type (Windows/Linux), OS state (generalized/specialized), publisher/offer/SKU metadata. It does not itself contain disk data.
- **Image Version**: the actual deployable artifact under a definition (e.g., `1.0.0`) — points to the source disk/snapshot/VM and defines which regions it's replicated to and how many replicas per region.

### Why use a Gallery instead of a standalone image

| Standalone Managed Image | Azure Compute Gallery |
|---|---|
| Single region | Multi-region replication |
| No built-in versioning | Native versioning (definition → versions) |
| Limited sharing (RBAC on the image resource only) | Fine-grained sharing across subscriptions/tenants, or publicly via Community Gallery |
| Manual tracking of "latest" image | Can target "latest version" automatically in deployments |

### Steps to Create a Gallery, Definition, and Version — Azure Portal UI

**1. Create the Gallery**
- Search **Azure Compute Galleries** → **+ Create**.
- Set **Subscription**, **Resource group**, **Gallery name**, **Region**.
- Optionally add a description.
- **Review + create** → **Create**.

**2. Create an Image Definition**
- Open the Gallery → **Image definitions** → **+ Create**.
- Fill in:
  - **Operating system** (Windows/Linux)
  - **VM generation** (Gen1/Gen2)
  - **OS state** (Generalized/Specialized)
  - **Publisher**, **Offer**, **SKU** (identifying metadata for the definition)
  - Optionally: recommended VM size, minimum/maximum vCPU and memory.
- **Review + create** → **Create**.

**3. Create an Image Version**
- Open the Image Definition → **Image versions** → **+ Create**.
- Set:
  - **Version number** (e.g., `1.0.0`)
  - **Source**: choose the source VM, managed disk, snapshot, or another image version to capture from.
  - **Exclude from latest** (toggle if this version shouldn't be picked up by "latest" deployments).
  - **Replication**: select target regions and replica count per region.
- **Review + create** → **Create**.

**4. Deploy a VM from the Gallery Image**
- **Create a VM** → **Image** → **See all images** → select the Gallery → choose the **Image Definition** → choose a specific **Version** (or "Latest").
- Continue the normal VM creation wizard.

## Quick Summary

| Task | Where in UI |
|---|---|
| Capture a VM as an image | VM → **Capture** |
| Create a gallery | **Azure Compute Galleries** → **+ Create** |
| Create an image definition | Gallery → **Image definitions** → **+ Create** |
| Create an image version | Image Definition → **Image versions** → **+ Create** |
| Deploy from image | **Create a VM** → **Image** → **See all images** |
